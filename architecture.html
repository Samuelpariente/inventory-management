Request Data Flow
1

User selects a filter

FilterBar.vue updates shared refs in useFilters.js composable — selectedPeriod, selectedLocation, selectedCategory, selectedStatus.

2

View reacts and calls API

A watch in each view fires getCurrentFilters(). The composable maps selectedLocation → warehouse and selectedPeriod → month, then passes the object to api.js.

3

HTTP request via Axios

api.js builds a URLSearchParams object and calls e.g. GET /api/orders?warehouse=SF&category=Sensors&status=Processing&month=2025-01.

4

FastAPI filters in-memory data

apply_filters() chains warehouse, category, status filters (skips all). filter_by_month() handles direct months and quarters (Q1-2025 → 3 months). Pydantic validates the result shape.

5

Frontend stores & renders

Response stored in a ref([]). Computed properties derive display values (totals, status counts, chart data). Templates iterate with v-for using unique keys (SKU, order ID, etc.).

KPI cards (inventory value, orders, fill rate, revenue YTD/MTD), order health chart, inventory distribution.

Order tracking with expandable line items. Status breakdown (Delivered / Shipped / Processing / Backordered).

Demand forecasting table grouped by trend direction (increasing / stable / decreasing). Current vs forecast comparison.

Spending

Revenue vs costs bar chart, monthly cost-flow stacked chart, procurement/operational/labor/overhead breakdown. Transaction details.

Reports

/reports → Reports.vue

Quarterly performance table, monthly revenue trend chart, MoM growth rates.

Backlog

/backlog → Backlog.vue

Shortage management by priority. Quantity-needed vs available, days delayed. Create purchase orders from modal.

Data Files (server/data/)

Stock items with SKU, warehouse, quantity, reorder point, unit cost, location.

Customer orders with nested line items, status, dates, warehouse, total value.

demand_forecasts.json

Current vs forecasted demand per SKU, with trend direction.

backlog_items.json

Shortage records: qty needed vs available, days delayed, priority.

spending.json

Spending summary, 12-month breakdown, and category totals.

transactions.json

Financial transactions with vendor, type, amount, warehouse.

purchase_orders.json

Purchase orders created from backlog items. Initially empty; grows at runtime.

Key Patterns

Global Filter System

  • Singleton composable useFilters.js
  • 4 filters: Period, Location, Category, Status
  • All views share the same filter refs
  • Maps: location → warehouse, period → month
  • Filters applied server-side per request

Reactivity Model

  • Raw data stored in ref([])
  • Display values in computed()
  • Computed cached until dependencies change
  • Unique keys in all v-for (SKU, ID)
  • Dates validated before parsing

Internationalization

  • English & Japanese supported
  • Locale stored in localStorage
  • Currency auto-switches: USD / JPY
  • Product/warehouse names translated
  • Fallback to English if key missing

Design System

  • Slate/gray palette (#0f172a, #64748b)
  • Status: green / blue / yellow / red
  • Custom SVG charts (no chart library)
  • CSS Grid for page layouts
  • No emojis in UI
